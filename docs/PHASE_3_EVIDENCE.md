# Phase 3 Tac View Evidence

> This is a historical record. On 2026-08-10, ADR (architecture decision
> record) 0015 replaced the SSR-island (server-side rendering island) checks in
> this phase. Tac now qualifies only with a plan that the client renders
> completely. ADR 0016 removes the experimental Yon view system.

## Status

Phase 3 was completed as a development milestone on 2026-07-26. It is not a
preview and not a supported Tachyon release. The normative contract and the
explicit deferrals are in [`PHASE_3_SPEC.md`](PHASE_3_SPEC.md).

## Delivered Outcome

The current `ty build` command does these things:

- parses bounded Tac templates;
- lowers them to View IR (intermediate representation) v1;
- emits client render plans and View Source Map v1;
- reuses only route artifacts that it has verified.

The build discovers Yon handlers for the manifests, but it never executes them.

The canonical `<logic>/<loop>` controls and the `<if>/<else>/<for>`
compatibility aliases are compiler syntax. Neither set ever appears in the emitted HTML.
A failed build keeps the last complete output.

## Behavioral Evidence

The normal workspace gate has 90 deterministic Rust tests:

- 6 Phase 1 acceptance tests that run the real binary;
- 5 Phase 2 handler acceptance tests that run the real binary;
- 7 Phase 3 view acceptance tests that run the real binary;
- 6 shared adversarial tests that run real JavaScript and Python processes;
- 5 tests for the contract registry and wire shapes;
- 7 repository policy tests;
- 48 core tests for the compiler, views, handlers, server, discovery and
  scaffolding;
- 6 diagnostic contract tests.

The current Phase 3 corpus proves these results:

- The build discovers JavaScript and Python Yon handlers without executing
  static fields or `GET()`. It rejects `yon.html`.
- These lower to a bounded client render plan: condition chains, loops,
  escaped interpolation, dynamic attributes, component properties, slots and
  ordinary web components.
- These fail with stable diagnostics: malformed expressions and controls,
  component cycles, missing component companions and independent source
  failures.
- View IR contains structural expressions but no evaluated values. Source maps
  point generated byte ranges to the page and component inputs.
- All component mount policies run after the browser creates the DOM.
  Activating policies copy only their registered companion modules.
- Incremental builds behave correctly:
  - unchanged Tac routes reuse artifacts that pass digest verification;
  - a component change invalidates routes;
  - corrupt state is treated as a safe cache miss;
  - `--no-incremental` forces compilation;
  - routes with only a handler emit no view artifact.

The repeatable browser gates build with the real Rust binary, serve fixtures
and control headless Chromium. They prove these behaviors:

- initial client rendering;
- public props;
- same-origin modules;
- component mount scheduling;
- structural updates that the browser owns;
- event handling;
- a `never` component that loads no module.

## Explicit Boundary

Phase 3 compiles deterministically to render plans that the browser owns. It
does not add any of these:

- production HTTP dispatch;
- arbitrary JavaScript expressions;
- raw HTML;
- SPA (single-page application) navigation;
- streaming;
- native rendering;
- WebSurface fallback;
- stable release packaging;
- handler sandboxing at the operating-system level.

Yon stays outside this pipeline.
