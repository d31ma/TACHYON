Where the file picker opens a panel

  Service language        macOS    Windows  Linux    iOS      Android  Browser tab
  JavaScript, TypeScript  panel    dialog   dialog   picker   picker   unsupported
  Rust                    panel    dialog   dialog   picker   picker   unsupported
  Swift                   panel    dialog   dialog   picker   picker   unsupported
  C#                      panel    dialog   dialog   picker   picker   unsupported
  Kotlin                  panel    dialog   dialog   picker   picker   unsupported

Every service uses the same file on every target. A Swift, C# or
Kotlin service asks for the picker with an uninitialized FilePicker
field and NeedsAll. In an app that does not link the language, the
service runs as WebAssembly in the page and its field still opens the
app's picker through the page. The iOS app opens the document picker
and the Android app opens the system document picker. In a browser
tab, available() is false and every call answers unsupported.

Limits on every host that opens a panel

  type filters     text/plain, application/json (empty: any file)
  read size        65,536 bytes of UTF-8 text
  handle lifetime  300 seconds, or until the service goes away
  handles          8 per service, 128 per app
  panels           one at a time; a second request is unavailable
  panel timeout    30 seconds, then cancelled
