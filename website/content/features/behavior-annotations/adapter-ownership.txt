Configuration returns only application-selected caches/http/entities adapters.
Each behavior context belongs to one owner. Derive its partition
from authenticated ownership, or declare a fixed partition for public data.
Cache authorization must return literal true for hits, misses and eviction;
@CacheKey parameters must cover every input that changes a result. The adapter enforces
entry quotas and atomic replacement. Yon contexts do not survive requests.

Explicit repository CRUD adapters own authorization and tenancy.
Structured queries additionally require authorizeEntity(command, execution).
Entity adapters own parameterized operations.
HTTP adapters honor redirect: 'error', credentials: 'omit', cancellation,
deadlines and the bounded response while reading. Never bundle server
credentials in Tac. No annotation adds SSR or native capabilities.

Stores, clients and converters: a service asks for them with Needs.
A store or client opens the context of its Setup itself; a converter
needs no context. A service that uses a behavior annotation on its own
method creates its context in OnStart with Behaviors.create.
Yon managed roles: Needs finds each marked field's provider; no
handwritten constructor is necessary, and Named names the provider.
HTTPClient request methods (GetRequest, PostRequest, ...) return
JSON types or models; annotations cannot rewrite a method or
constructor signature.
