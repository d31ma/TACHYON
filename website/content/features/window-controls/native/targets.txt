Choose one native ReportService alternative for the target.

  Swift     macOS, iOS
  C#        Windows
  Kotlin    Android

Rust needs no alternative: client/services/ReportService.rs works in the
page and when a macOS, Linux or Windows app links it, because Rust fills
the WindowControls field with Default.

The native/ folder here separates documentation alternatives. It is not
an additional application discovery root. Put the chosen file in your
application's client/services/ReportService.<extension>, replacing that
language's browser example. Keep the same page and component HTML.

Each native alternative is Service + NeedsAll. Its typed WindowControls
field is filled by Tachyon's native activation provider. The service does
not construct the provider or import a platform API. The native host
registers its window adapter and checks the manifest grants again.

The manifest grants minimize, resize and title. It does not grant close,
maximize or fullscreen. Browser tabs have no native window and refuse
these calls. The macOS host runs the controls on the app's own window,
and a macOS test checks this on a real app window. The Linux (GTK) host
has the controls too. A Linux test runs the generated app under Xvfb with
a window manager: a Rust page service sets the title, resizes and
minimizes the app's window, and a close without its grant is refused. On
Windows, a test that needs MSVC drives the host's control code against a
real Win32 window, without the full app or WebView2. The Android check
only type-checks the code against the SDK; it does not run on a device.
