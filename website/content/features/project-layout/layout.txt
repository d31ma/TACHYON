What `ty init` lays out

  client/
    pages/        one directory per route, holding a tac.html
    components/   a two-level path, <product-card>: a view and its styles
    services/     one <Name>Service class per file, addressed as {name.field}
    clients/      collaborators a service injects; also stores/,
                  setups/, entities/, helpers/ and converters/
    models/       data types in TypeScript, Rust, C#, Dart, Kotlin or Swift,
                  never shipped on their own
    tests/        <Name>Test files run by ty test
    shared/       published as-is, imported by both halves

  server/
    routes/       yon.* files exposing the fixed Handler type
    services/     optional ordinary application modules
    stores/       optional ordinary application modules
    clients/      optional ordinary application modules
    helpers/      optional helper classes, and programs reached with
                  relay(...) or a @Gateway command
    models/       data types in TypeScript, Rust, C#, Dart, Kotlin, Java,
                  Python or PHP
    tests/        <Name>Test files run by ty test
    vendor/       third-party code, checked in
    config/       configuration a handler reads
    data/         files a handler reads or writes
    gateways/     reserved: Tachyon generates @Gateway units here, never
                  author files in it

  client/manifest.json   name, icons, start_url, and in tac: the
                        application identity and window, metadata,
                        shared assets, cache rules and the sitemap

tac.html, client/services and yon.* Handler entry points are framework
contracts, and so are the plural role folders: a role-annotated type is
discovered by the folder it sits in and the filename matching its type
(ADR 0031). models/ holds data types only (ADR 0041, ADR 0043), and
tests/ is where ty test looks. The remaining names are starter
conventions and can be changed or omitted.
