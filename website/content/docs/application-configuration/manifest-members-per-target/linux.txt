Linux

name, short_name
  honored: the .desktop Name and the window title

start_url
  honored: the page the app opens first

icons
  adapted: icons: the Linux app copies the largest raster icon into share/icon.png without resizing it. Release packages install each raster icon in the hicolor icon theme at its declared size.

theme_color
  adapted: theme_color colors a GTK header bar on the Linux app, with black or white title text, when it is written as #rgb or #rrggbb. The header bar then replaces the window manager's title bar. Other color forms keep the standard title bar. With titleBar "integrated" there is no header bar: the page colors the top edge.

background_color
  adapted: background_color is not applied to the Linux app yet.

display
  adapted: display "fullscreen" starts the Linux app full screen. The other values open a standard window.

orientation
  not applicable: orientation has no meaning for a Linux window.

tachyon (top-level)
  refused with TY1601: The top-level tachyon member is gone. Move its values into tac (ADR 0052).

other standard manifest members
  adapted: The Linux app does not use the standard members scope, id, lang, shortcuts, share_target, file_handlers, protocol_handlers or display_override. They are published only for browsers. description is used only by release packages, as the AppStream summary and the .deb description.

tac.application
  honored: the app's identity, window and menus

tac.application.id
  adapted: tac.application.id names the .desktop file as written. The GTK application id changes each hyphen to an underscore, and release packages use that id for their desktop file, AppStream metainfo and icon.

tac.application.version
  adapted: A Linux .desktop file has no application version key, so tac.application.version is written as X-Tachyon-Version. Release packages also use it as the AppStream release and the .deb version, so a release needs a version that starts with a digit (TY1601).

tac.application.build
  adapted: A Linux .desktop file has no build number key, so tac.application.build is written as X-Tachyon-Build. Release packages use it as the .deb revision, after the version.

tac.application.minimumSystem
  adapted: On Linux, tac.application.minimumSystem.linux is the WebKitGTK version (2.40 unless set; 2.46 with a Dart, Kotlin or Java web service). The app checks it when it starts and explains an older WebKitGTK instead of opening a blank window.

tac.application.window.width, height
  honored: the first size of the page inside the window

tac.application.window.minWidth, minHeight
  honored: the smallest size of the page inside the window

tac.application.window.controls
  honored: close, fullscreen, maximize, minimize, resize and title, from page services and linked Rust services

tac.application.window.titleBar
  adapted: tac.application.window.titleBar "integrated" lets the Linux page reach the top edge under GTK's own window buttons, with the same insets and drag regions as macOS (ADR 0098). The menu bar moves into a main menu button beside the window buttons, as in GNOME apps.

tac.application.window.titleBarButtonInset
  adapted: tac.application.window.titleBarButtonInset places the Linux window buttons: top is the distance from the top edge, and leading the distance from the window edge where each group of buttons sits, because the desktop's button layout decides which side holds the close button.

tac.application.menus
  honored: items in the File, View and Help menus of the window's menu bar

tac.application.rust
  honored: vendored crates linked into the app's Rust services

tac.application.rust.executables
  honored: helper programs in bin/ beside the app

tac.origin
  not applicable: tac.origin is for search engines and the web server. The Linux app bundle still holds sitemap.xml and robots.txt, but nothing reads them there.

tac.sitemap
  not applicable: tac.sitemap adds entries to sitemap.xml for search engines. The Linux app bundle holds the file, but nothing reads it there.

tac.scripts
  honored: the same page head as the web build

tac.blockingScripts
  honored: the same page head as the web build

tac.styles
  honored: the same page head as the web build

tac.styleSources
  honored: the same checked files, bundled into the app

tac.scriptSources
  honored: the same checked files, bundled into the app

tac.cache
  adapted: tac.cache rules apply to Yon reads in the Linux app, but the kept reads last only while the app runs: the web view session is not kept yet (ST1).

tac.metadata
  adapted: tac.metadata tags are written into each page, but search-engine and sharing tags do nothing inside the Linux app.

tac.application.permissions
  not applicable: tac.application.permissions is not used by the Linux app: it shows no permission prompt of its own, and GeoClue and the desktop settings decide location and notifications.

tac.browserApis
  honored: the same grant list in the page

tac.browserApis clipboard
  honored: the web view's navigator.clipboard; the host lets the app's own pages read text copied in other apps

tac.browserApis share
  adapted: Linux has no system share sheet, so share in the Linux app copies the url, or else the text or title, to the clipboard.

tac.browserApis notifications
  adapted: notifications in the Linux app are desktop notifications (GNotification). Linux does not ask the user first: requestPermission answers granted, and the desktop's notification settings decide what is shown.

tac.browserApis geolocation
  honored: the web view's navigator.geolocation through GeoClue, allowed by the host for the app's own pages

tac.browserApis preferenceStrings
  adapted: preferenceStrings in the Linux app live only while the app runs: the web view does not keep storage yet (ST1).

tac.nativeCapabilities
  adapted: tac.nativeCapabilities filePicker is not built for Linux yet. FilePicker answers unsupported (FP3).

tac.elements
  adapted: tac.elements are bundled into the Linux app for its own pages only. Other sites cannot load them from the app.

tac.python
  honored: Pyodide in the web view, checked in code only (ADR 0093)

tac.budgets
  not applicable: tac.budgets is checked only by web release builds. The Linux app loads its bundle from disk, so route sizes are not measured (ADR 0074).

tac.outgoing
  honored: the build checks request hosts and the scheme handler's connect-src allows only them

tac.yon
  honored: the Linux app sends page and linked Rust service calls to tac.yon.origin from tachyon://app, and its connect-src allows it (ADR 0103, run under Xvfb)

application lifetime services
  honored: Rust services that start with the app and stop when it quits

standard menu bar without declared items
  honored: File, Edit and Window menus, shown even when the manifest declares no items

Edit menu
  honored: Undo, Redo, Cut, Copy, Paste and Select All; Redo is Ctrl+Shift+Z

Window menu
  adapted: The Linux Window menu has Minimize and Maximize, with no shortcuts.

menu shortcuts with control
  adapted: A shortcut with control gets Ctrl on Linux, like command. Shortcuts that then collide stop the build (TY1601).

page accessibility (roles and names through the system accessibility API)
  honored: the web view's AT-SPI tree; scripts/linux/a11y-probe.py checks the window name, menu bar, page roles and names, and activation

window drag regions (data-tac-drag-region)
  honored: with titleBar "integrated", dragging a marked element moves the window and a double-click follows the desktop's title bar setting

external links
  honored: http, https and mailto links open in the default browser or mail app (GtkUriLauncher)

deep links
  adapted: The Linux app cannot be opened at a route from a link yet (LK2).

background and foreground signal
  honored: ApplicationStateChanged when no app window is active or the window is suspended, and when it is active again

stored data (IndexedDB, Cache API, LocalState)
  adapted: Stored data in the Linux app is lost when the app quits: the web view session is not kept yet (ST1).

Content-Security-Policy
  honored: the native host policy

reaching Yon
  honored: HTTP calls, streams, sockets and topics from pages and linked Rust services go to tac.yon.origin, which lists tachyon://app in server.origins (ADR 0103)

natively linked service languages
  honored: Rust services are linked into the app; other languages run in the page

build architecture (--arch)
  adapted: --arch does not choose the Linux architecture: the Linux app is built for the build machine's architecture.

release packaging
  honored: ty bundle --release builds an AppImage and a .deb that install the app, its command, desktop file, AppStream metainfo and icons; both use the system's GTK 4 and WebKitGTK 6. Other builds are a folder

incremental route reuse
  honored: routes are reused from the previous app's web folder; --no-incremental turns this off

byte-identical rebuilds
  honored: SOURCE_DATE_EPOCH and a path map reach cc and rustc, and SOURCE_DATE_EPOCH reaches dpkg-deb and mksquashfs; two packaged builds give the same artifact-manifest.json digests
