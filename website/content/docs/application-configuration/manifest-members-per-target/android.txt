Android

name, short_name
  honored: app_name in strings.xml

start_url
  honored: the page the app opens first

icons
  adapted: icons: the Android app copies the largest raster icon into mipmap-xxxhdpi without resizing it.

theme_color
  adapted: theme_color fills the Android status and navigation bars and picks dark or light bar icons by contrast, when it is written as #rgb or #rrggbb. With titleBar "integrated" the page draws under the status bar instead. Other color forms keep the system bars.

background_color
  adapted: background_color colors the Android window, the splash screen (Android 12 and later) and the web view behind the page, when it is written as #rgb or #rrggbb. Other color forms keep the system background.

display
  adapted: display "fullscreen" hides the Android status and navigation bars; a swipe from the edge shows them for a moment. The other values keep the system bars.

orientation
  adapted: orientation sets the Android activity's screenOrientation: portrait and landscape follow the user's rotation lock between both turns, the -primary and -secondary values fix one turn, natural ignores the sensor, and any (or no value) turns with the device.

tachyon (top-level)
  refused with TY1601: The top-level tachyon member is gone. Move its values into tac (ADR 0052).

other standard manifest members
  adapted: The Android app does not use the standard members scope, id, description, lang, shortcuts, share_target, file_handlers, protocol_handlers or display_override. They are published only for browsers.

tac.application
  honored: the app's identity and menus

tac.application.id
  adapted: tac.application.id becomes the Android applicationId after characters that Android refuses are replaced.

tac.application.version
  honored: versionName

tac.application.build
  honored: versionCode; a build above 2100000000 stops the build (TY1601)

tac.application.minimumSystem
  adapted: On Android, tac.application.minimumSystem.android is the minSdk API level (26 to 35). Dart and Java web services need Android System WebView 119, and component styles need WebView 118 for CSS @scope; Google Play updates the web view apart from Android, so neither need raises the API level (ADR 0108).

tac.application.links
  adapted: tac.application.links: the Android app claims the listed schemes, and https links to the listed hosts with autoVerify, and opens them at their route, or at start_url when the route is unknown. Android verifies the hosts only when each one serves /.well-known/assetlinks.json with the app's signing certificate (TAC_ANDROID_CERT_SHA256); until then it asks which app opens their links. On the emulator, a verified hosted domain opened its links in the app without asking (LINKS); a physical device has not been checked.

tac.application.window.width, height
  not applicable: tac.application.window width and height have no meaning on Android: the system sizes the app.

tac.application.window.minWidth, minHeight
  not applicable: tac.application.window minWidth and minHeight have no meaning on Android: the system sizes the app.

tac.application.window.controls
  adapted: tac.application.window.controls on Android act on the activity: close finishes it, minimize moves it to the back, maximize makes its window fill the screen, fullscreen hides the system bars, resize sets its window size in density-independent pixels, and title sets the activity title. On the emulator, granted minimize, resize and title acted from the page and a linked Kotlin service, title also from a linked Rust service,, granted maximize and fullscreen acted from a linked Kotlin service, fullscreen from the page hid and showed the system bars, close from the page finished the activity and refused a control that reached it after close started, and ungranted controls were refused (RM3).

tac.application.window.titleBar
  adapted: tac.application.window.titleBar "integrated" lets the Android page draw edge to edge, under the status bar. --tac-titlebar-height is the status bar height, and the leading and trailing insets are the side system-bar and display-cutout insets. The navigation bar still pads the page. There are no window buttons and no drag regions (ADR 0098).

tac.application.window.titleBarButtonInset
  not applicable: tac.application.window.titleBarButtonInset has no meaning on Android: the app has no window buttons.

tac.application.menus
  adapted: app bar overflow menu: route items are listed in the overflow menu of an app bar, and their shortcuts use Ctrl on a hardware keyboard. Action items call a method of an application service and are enabled only while the page listens for their event (MN1b).

tac.application.tray
  refused with TY1601: Android has no tray. Put these controls in the page instead (ADR 0107).

tac.application.tray.template
  not applicable: tac.application.tray.template has no meaning on Android, which refuses tac.application.tray.

tac.application.tray.closeHidesWindow
  not applicable: tac.application.tray.closeHidesWindow has no meaning on Android, which refuses tac.application.tray.

tac.application.tray.dock
  not applicable: tac.application.tray.dock has no meaning on Android, which refuses tac.application.tray.

tac.application.rust
  run owed: vendored crates linked into the app's Rust services, built for arm64-v8a and x86_64; platformDependencies.android applies only here; still to run: an Android app whose Rust service uses a vendored crate, on the emulator

tac.application.rust.executables
  refused with TY1601: An Android app may not start other programs. Do the work in a service, or remove tac.application.rust.executables for this target.

tac.origin
  not applicable: tac.origin is for search engines and the web server. The Android app bundle still holds sitemap.xml and robots.txt, but nothing reads them there.

tac.sitemap
  not applicable: tac.sitemap adds entries to sitemap.xml for search engines. The Android app bundle holds the file, but nothing reads it there.

tac.scripts
  honored: the same page head as the web build

tac.blockingScripts
  honored: the same page head as the web build

tac.styles
  honored: the same page head as the web build

tac.styleSources
  honored: the same checked files, bundled into the app

tac.scriptSources
  honored: the same checked files, bundled into the app

tac.cache
  adapted: tac.cache rules apply to Yon reads in the Android app, but a read kept shortly before the system stops the app is not always there after a relaunch: the web view does not always keep such Cache Storage entries. In airplane mode on the Android 15 emulator, a network-first and a cache-first Yon read answered from Cache Storage (RM3).

tac.metadata
  adapted: tac.metadata tags are written into each page, but search-engine and sharing tags do nothing inside the Android app.

tac.application.permissions
  honored: the rationale Android shows before it asks again for location or notifications, and the name of the notification channel; the location rationale and the channel name ran on the Android 15 emulator in scripts/android/browser-apis-test.mjs (RM3)

tac.browserApis
  honored: the same grant list in the page

tac.browserApis clipboard
  honored: ClipboardManager, through the host bridge; the clipboard round trip ran on the Android 15 emulator in scripts/android/browser-apis-test.mjs (RM3)

tac.browserApis share
  adapted: share in the Android app opens the system share sheet. ShareFinished arrives when the sheet opens, because Android does not tell the app whether the user shared. The share sheet opened on the Android 15 emulator in scripts/android/browser-apis-test.mjs (RM3).

tac.browserApis notifications
  honored: NotificationManagerCompat through the host bridge, with the POST_NOTIFICATIONS question on Android 13 and later and a channel named from tac.application.permissions.notifications; the question and a posted notification ran on the Android 15 emulator in scripts/android/browser-apis-test.mjs (RM3)

tac.browserApis geolocation
  honored: the web view's navigator.geolocation, after the host asks for ACCESS_FINE_LOCATION through WebChromeClient; the question and a test-provider position ran on the Android 15 emulator in scripts/android/browser-apis-test.mjs (RM3)

tac.browserApis preferenceStrings
  honored: the web view's localStorage, kept on disk; a write was read back after a relaunch on the Android 15 emulator in scripts/android/page-checks-test.mjs (RM3)

tac.nativeCapabilities
  honored: filePicker opens the system document picker (ACTION_OPEN_DOCUMENT) for page, Kotlin and Rust services, and for Swift and C# services, which run as WebAssembly on Android and reach the picker through the page; each chose, read and cancelled on the API 35 emulator (FP2)

tac.elements
  adapted: tac.elements are bundled into the Android app for its own pages only. Other sites cannot load them from the app.

tac.python
  honored: Pyodide in the web view, loaded from https://appassets.tachyon.local; a Python service answered on the Android 15 emulator in scripts/android/python-service-test.mjs (ADR 0093)

tac.budgets
  not applicable: tac.budgets is checked only by web release builds. The Android app loads its bundle from disk, so route sizes are not measured (ADR 0074).

tac.outgoing
  adapted: The Android app lets page requests reach the hosts in tac.outgoing.hosts over https only: the platform refuses cleartext http and ws. It asks for the INTERNET permission only when the list names a host.

tac.yon
  honored: the page and its linked Kotlin and Rust HTTP clients reach tac.yon.origin from https://appassets.tachyon.local, the app asks for the INTERNET permission, and a local http origin may use cleartext to that one host only; run by scripts/android/yon-origin-test.mjs and rust-services-test.mjs on the Android 15 emulator, also on its Google Play production image (ADR 0103)

tac.dotnet

application lifetime services
  honored: Rust services that start with the first activity and stop once when the activity finishes; a rotation keeps them, and a later launch in the same process starts new ones (LT1, emulator)

standard menu bar without declared items
  not applicable: Without declared items, an Android app shows no app bar.

Edit menu
  not applicable: The system text toolbar handles text on Android.

Window menu
  not applicable: The system owns the Android window.

menu shortcuts with control
  adapted: A shortcut with control gets Ctrl on Android, like command. Shortcuts that then collide stop the build (TY1601).

page accessibility (roles and names through the system accessibility API)
  honored: the web view's accessibility tree, which TalkBack reads; on the Android 15 emulator scripts/android/accessibility-test.mjs read the heading, image, text field, button and link by class and name through UiAutomation, ran ATF-style checks, and typed into the field, pressed the button and opened the link through it (AX1)

window drag regions (data-tac-drag-region)
  not applicable: An Android app has no window to move.

external links
  honored: http, https and mailto links open in the default browser or mail app (ACTION_VIEW), and a link with a user name opens nothing; run on the Android 15 emulator by scripts/android/page-checks-test.mjs (RM3)

deep links
  honored: with tac.application.links, a link with a listed scheme opens the app at its route, run on the emulator; https links to listed hosts are described under tac.application.links

system back navigation
  honored: Back and the back gesture go back in the web view's history (OnBackInvokedCallback from Android 13, onBackPressed before); on the first route Back leaves the app the system way; scripts/android/system-back-test.mjs ran the Back key and the edge gesture on the Android 15 (API 35) emulator with WebView 124 (SB1)

background and foreground signal
  honored: ApplicationStateChanged on onStop and onStart, heard by page services and linked Kotlin services; run on the Android 15 emulator by scripts/android/page-checks-test.mjs (RM3)

stored data (IndexedDB, Cache API, LocalState)
  adapted: Store rows and LocalState values in the Android app are kept on disk. A Cache API entry written shortly before the system stops the app is not always kept, so a Cached method may run again after a relaunch.

service worker
  not applicable: The Android app registers no service worker: its pages load from the app bundle. With tac.yon.origin set, the page applies tac.cache rules to Yon reads itself; without it, tac.cache has no effect in the app.

Content-Security-Policy
  honored: the native host policy, which also allows the host's bridge script by its hash

reaching Yon
  adapted: The Android app's pages load from https://appassets.tachyon.local, so same-origin requests reach no Yon. HTTP calls, streams, sockets and topics from pages, and linked Kotlin and Rust HTTP clients, reach the Yon at tac.yon.origin, run on the Android 15 emulator by scripts/android/yon-origin-test.mjs and rust-services-test.mjs (NET2, MR2). The page also holds a linked Kotlin service's stream and socket clients and delivers their messages to it (LS1); an emulator run of that is still owed.

natively linked service languages
  honored: Kotlin and Rust services are linked into the app, with Kotlin chosen when a service has both; other languages run in the page

build architecture (--arch)
  honored: --arch arm64, x64 or universal, the default; the Rust library is built for arm64-v8a, x86_64 or both, and Gradle's abiFilters name the same ABIs. An app without Rust services holds no native code and runs on every ABI

development code signing
  honored: a debug APK is signed with the build machine's Android debug keystore

release packaging
  honored: ty bundle --release builds an APK and an AAB signed with the keystore that TAC_ANDROID_KEYSTORE names, shrunk by R8 with keep rules for the host, bridge and service classes; other builds are a debug APK

incremental route reuse
  honored: routes are reused from the previous app's web folder; --no-incremental turns this off

development preview (ty preview)
  honored: ty preview --target android installs the app on the emulator through adb, forwards the port with adb reverse and loads its pages from the development server, so edits arrive as hot updates; a manifest or linked service edit reinstalls the app (run on an API 35 emulator by scripts/android/dev-loop-test.mjs, NET5)

byte-identical rebuilds
  honored: the Android build turns on Gradle's reproducible archives and drops Gradle's build folders from the output; the debug APK is signed with the build machine's debug key, so it matches only on the same machine; a_packaged_android_app_is_byte_identical_when_built_twice passed on a Mac (RM3)

running without a signed-in desktop session
  honored: the app runs in a headless Android emulator
