Android

name, short_name
  honored: app_name in strings.xml

start_url
  honored: the page the app opens first

icons
  adapted: icons: the Android app copies the largest raster icon into mipmap-xxxhdpi without resizing it.

theme_color
  adapted: theme_color fills the Android status and navigation bars and picks dark or light bar icons by contrast, when it is written as #rgb or #rrggbb. With titleBar "integrated" the page draws under the status bar instead. Other color forms keep the system bars.

background_color
  adapted: background_color colors the Android window, the splash screen (Android 12 and later) and the web view behind the page, when it is written as #rgb or #rrggbb. Other color forms keep the system background.

display
  adapted: display "fullscreen" hides the Android status and navigation bars; a swipe from the edge shows them for a moment. The other values keep the system bars.

orientation
  adapted: orientation sets the Android activity's screenOrientation: portrait and landscape follow the user's rotation lock between both turns, the -primary and -secondary values fix one turn, natural ignores the sensor, and any (or no value) turns with the device.

tachyon (top-level)
  refused with TY1601: The top-level tachyon member is gone. Move its values into tac (ADR 0052).

other standard manifest members
  adapted: The Android app does not use the standard members scope, id, description, lang, shortcuts, share_target, file_handlers, protocol_handlers or display_override. They are published only for browsers.

tac.application
  honored: the app's identity and menus

tac.application.id
  adapted: tac.application.id becomes the Android applicationId after characters that Android refuses are replaced.

tac.application.version
  honored: versionName

tac.application.build
  honored: versionCode; a build above 2100000000 stops the build (TY1601)

tac.application.minimumSystem
  adapted: On Android, tac.application.minimumSystem.android is the minSdk API level (26 to 35). Dart and Java web services need Android System WebView 119, which Google Play updates apart from Android, so their need does not raise the API level.

tac.application.links
  adapted: tac.application.links: the Android app claims the listed schemes, and https links to the listed hosts with autoVerify, and opens them at their route, or at start_url when the route is unknown. Android verifies the hosts only when each one serves /.well-known/assetlinks.json with the app's signing certificate (TAC_ANDROID_CERT_SHA256); until then it asks which app opens their links.

tac.application.window.width, height
  not applicable: tac.application.window width and height have no meaning on Android: the system sizes the app.

tac.application.window.minWidth, minHeight
  not applicable: tac.application.window minWidth and minHeight have no meaning on Android: the system sizes the app.

tac.application.window.controls
  adapted: tac.application.window.controls on Android act on the activity: close finishes it, minimize moves it to the back, maximize makes its window fill the screen, fullscreen hides the system bars, resize sets its window size in density-independent pixels, and title sets the activity title. On the emulator, granted minimize, resize and title acted from the page and a linked Kotlin service, title also from a linked Rust service, and ungranted controls were refused. A granted close, maximize or fullscreen has not run yet.

tac.application.window.titleBar
  adapted: tac.application.window.titleBar "integrated" lets the Android page draw edge to edge, under the status bar. --tac-titlebar-height is the status bar height, and the leading and trailing insets are the side system-bar and display-cutout insets. The navigation bar still pads the page. There are no window buttons and no drag regions (ADR 0098).

tac.application.window.titleBarButtonInset
  not applicable: tac.application.window.titleBarButtonInset has no meaning on Android: the app has no window buttons.

tac.application.menus
  adapted: app bar overflow menu: route items are listed in the overflow menu of an app bar, and their shortcuts use Ctrl on a hardware keyboard. Action items stop the build (TY1601) until Android has the application lifetime (MN1b).

tac.application.tray
  refused with TY1601: Android has no tray. Put these controls in the page instead (ADR 0107).

tac.application.tray.template
  not applicable: tac.application.tray.template has no meaning on Android, which refuses tac.application.tray.

tac.application.tray.closeHidesWindow
  not applicable: tac.application.tray.closeHidesWindow has no meaning on Android, which refuses tac.application.tray.

tac.application.tray.dock
  not applicable: tac.application.tray.dock has no meaning on Android, which refuses tac.application.tray.

tac.application.rust
  run owed: vendored crates linked into the app's Rust services, built for arm64-v8a and x86_64; platformDependencies.android applies only here; still to run: an Android app whose Rust service uses a vendored crate, on the emulator

tac.application.rust.executables
  refused with TY1601: An Android app may not start other programs. Do the work in a service, or remove tac.application.rust.executables for this target.

tac.origin
  not applicable: tac.origin is for search engines and the web server. The Android app bundle still holds sitemap.xml and robots.txt, but nothing reads them there.

tac.sitemap
  not applicable: tac.sitemap adds entries to sitemap.xml for search engines. The Android app bundle holds the file, but nothing reads it there.

tac.scriptSources
  honored: the same checked files, bundled into the app

tac.cache
  adapted: tac.cache rules apply to Yon reads in the Android app, but a read kept shortly before the system stops the app is not always there after a relaunch: the web view does not always keep such Cache Storage entries.

tac.metadata
  adapted: tac.metadata tags are written into each page, but search-engine and sharing tags do nothing inside the Android app.

tac.application.permissions

tac.browserApis

tac.browserApis share
  adapted: share in the Android app opens the system share sheet. ShareFinished arrives when the sheet opens, because Android does not tell the app whether the user shared. A run of the share sheet on the emulator is still owed.

tac.browserApis notifications
  run owed: NotificationManagerCompat through the host bridge, with the POST_NOTIFICATIONS question on Android 13 and later and a channel named from tac.application.permissions.notifications; still to run: the POST_NOTIFICATIONS question and a posted notification in scripts/android/browser-apis-test.mjs on the emulator

tac.browserApis geolocation
  run owed: the web view's navigator.geolocation, after the host asks for ACCESS_FINE_LOCATION through WebChromeClient; still to run: the ACCESS_FINE_LOCATION question and a test-provider position in scripts/android/browser-apis-test.mjs on the emulator

tac.browserApis preferenceStrings
  run owed: the web view's localStorage, kept on disk; still to run: a preferenceStrings write read back after a relaunch on the emulator

tac.nativeCapabilities
  not applied: tac.nativeCapabilities filePicker is not built for Android yet. FilePicker answers unsupported (FP2).

tac.elements
  adapted: tac.elements are bundled into the Android app for its own pages only. Other sites cannot load them from the app.

tac.python
  run owed: Pyodide in the web view (ADR 0093); still to run: a Python service in the Android emulator gate (ADR 0093)

tac.budgets
  not applicable: tac.budgets is checked only by web release builds. The Android app loads its bundle from disk, so route sizes are not measured (ADR 0074).

tac.outgoing
  adapted: The Android app lets page requests reach the hosts in tac.outgoing.hosts over https only: the platform refuses cleartext http and ws. It asks for the INTERNET permission only when the list names a host.

tac.yon
  honored: the page and its linked Kotlin and Rust HTTP clients reach tac.yon.origin from https://appassets.tachyon.local, the app asks for the INTERNET permission, and a local http origin may use cleartext to that one host only; run by scripts/android/yon-origin-test.mjs and rust-services-test.mjs on the Android 15 emulator (ADR 0103)

application lifetime services
  refused with TY1406: Rust services are linked into the Android app, but none starts with the app yet (LT1). Use a page or singleton service.

standard menu bar without declared items
  not applicable: Without declared items, an Android app shows no app bar.

Edit menu
  not applicable: The system text toolbar handles text on Android.

Window menu
  not applicable: The system owns the Android window.

menu shortcuts with control
  adapted: A shortcut with control gets Ctrl on Android, like command. Shortcuts that then collide stop the build (TY1601).

page accessibility (roles and names through the system accessibility API)
  run owed: the pages reach TalkBack through the web view; still to run: an accessibility check of roles and names on the emulator (AX1)

window drag regions (data-tac-drag-region)
  not applicable: An Android app has no window to move.

external links
  run owed: http, https and mailto links open in the default browser or mail app (ACTION_VIEW); still to run: an http, https and mailto link from a page on the emulator

deep links
  honored: with tac.application.links, a link with a listed scheme opens the app at its route, run on the emulator; https links to listed hosts are described under tac.application.links

background and foreground signal
  run owed: ApplicationStateChanged on onStop and onStart; still to run: onStop and onStart on the emulator

stored data (IndexedDB, Cache API, LocalState)
  adapted: Store rows and LocalState values in the Android app are kept on disk. A Cache API entry written shortly before the system stops the app is not always kept, so a Cached method may run again after a relaunch.

service worker
  not applicable: The Android app registers no service worker: its pages load from the app bundle. With tac.yon.origin set, the page applies tac.cache rules to Yon reads itself; without it, tac.cache has no effect in the app.

Content-Security-Policy
  honored: the native host policy, which also allows the host's bridge script by its hash

reaching Yon
  adapted: The Android app's pages load from https://appassets.tachyon.local, so same-origin requests reach no Yon. HTTP calls, streams, sockets and topics from pages, and linked Kotlin and Rust HTTP clients, reach the Yon at tac.yon.origin, run on the Android 15 emulator by scripts/android/yon-origin-test.mjs and rust-services-test.mjs (NET2, MR2). The page also holds a linked Kotlin service's stream and socket clients and delivers their messages to it (LS1); an emulator run of that is still owed.

natively linked service languages
  honored: Kotlin and Rust services are linked into the app, with Kotlin chosen when a service has both; other languages run in the page

build architecture (--arch)
  adapted: --arch does not choose Android ABIs. An app with Rust services carries its Rust library for arm64-v8a and x86_64, so it installs on 64-bit Arm phones and x86_64 emulators only; without Rust services the APK holds no native code and runs on every ABI.

development code signing
  honored: a debug APK is signed with the build machine's Android debug keystore

release packaging
  honored: ty bundle --release builds an APK and an AAB signed with the keystore that TAC_ANDROID_KEYSTORE names; other builds are a debug APK

incremental route reuse
  honored: routes are reused from the previous app's web folder; --no-incremental turns this off

byte-identical rebuilds
  run owed: the Android build turns on Gradle's reproducible archives and drops Gradle's build folders from the output; the debug APK is signed with the build machine's debug key, so it matches only on the same machine; still to run: a_packaged_android_app_is_byte_identical_when_built_twice with ANDROID_HOME (TL2)

running without a signed-in desktop session
  honored: the app runs in a headless Android emulator
