Windows

name, short_name
  honored: the window title and the executable name

start_url
  honored: the page the app opens first

icons
  adapted: icons: the Windows app wraps the largest icon whose declared size is at most 256 pixels as its .ico file. With no such icon, the app has no icon. A --release MSIX package copies, without resizing, the smallest PNG icon that covers each tile (44, 50 and 150 pixels), or the largest PNG icon; with no PNG icon its tiles are plain squares in theme_color.

theme_color
  adapted: theme_color colors the title bar of the Windows 11 app, with black or white title text, when it is written as #rgb or #rrggbb. Other color forms, and Windows 10, keep the system title bar color. On a signed-in Windows 11 desktop every caption pixel the gate sampled took the color (SD1).

background_color
  run owed: background_color paints the Windows window and is WebView2's default background before the page paints, when it is written as #rgb or #rrggbb; with titleBar "integrated" only WebView2 takes it, and other color forms keep the system background; still to run: the WebView2 page backdrop on a signed-in Windows desktop

display
  adapted: display "fullscreen" starts the Windows app borderless and full screen; the page leaves it only with the fullscreen window control. The other values open a standard window.

orientation
  not applicable: orientation has no meaning for a Windows window.

tachyon (top-level)
  refused with TY1601: The top-level tachyon member is gone. Move its values into tac (ADR 0052).

other standard manifest members
  adapted: The Windows app does not use the standard members scope, id, description, lang, shortcuts, share_target, file_handlers, protocol_handlers or display_override. They are published only for browsers.

tac.application
  honored: the app's identity, window and menus

tac.application.id
  adapted: tac.application.id becomes the Windows assembly identity name with each dot changed to a hyphen. A --release build also makes it the MSIX package name, with every character other than a letter, digit, dot or hyphen changed to a hyphen; an id that is then shorter than 3 or longer than 50 characters stops the release build (TY1601). C# service storage and the telemetry file use it as written.

tac.application.version
  honored: the executable's file and product version, the manifest assemblyIdentity and, with --release, the MSIX package version; a version that is not one to three numbers up to 65535 stops the build (TY1601)

tac.application.build
  honored: the fourth number of the executable's file version and, with --release, of the MSIX package version; a build above 65535 stops the build (TY1601)

tac.application.minimumSystem
  adapted: On Windows, tac.application.minimumSystem.windows is the WebView2 Runtime version (86.0 unless set; 119.0 with a Dart, Kotlin or Java web service). The app checks it when it starts and explains a missing or older runtime instead of opening a blank window.

tac.application.links
  adapted: tac.application.links: the Windows app registers the listed schemes for the current user when it starts (a --release MSIX package declares them as windows.protocol extensions instead), and opens their links at their route, or at start_url when the route is unknown. A link that arrives while the app runs goes to the open window. A --release MSIX package also declares the listed hosts as app URI handlers, and the web build writes /.well-known/windows-app-web-link when TAC_WINDOWS_CERTIFICATE_PUBLISHER is set; Windows then opens links to the hosts that the shell launches in the app, while links clicked in Edge or another browser stay in it. The unpackaged app leaves links to the hosts in the browser. No package has opened a link from a hosted domain yet.

tac.application.window.width, height
  honored: the client area, in device-independent pixels

tac.application.window.minWidth, minHeight
  honored: the smallest client area the user can drag to, in device-independent pixels

tac.application.window.controls
  honored: close, fullscreen, maximize, minimize, resize and title, called from a page inside WebView2 on a signed-in Windows desktop (SD1)

tac.application.window.titleBar
  adapted: tac.application.window.titleBar "integrated" lets the Windows page reach the top edge under the system caption buttons, with the same insets as macOS and drag regions that WebView2 handles (ADR 0098). The menu bar moves into the window menu (Alt+Space, or a right-click on a drag region). The page covers the top edge, so the window resizes from its sides and bottom. Not yet run on a signed-in desktop (SD1).

tac.application.window.titleBarButtonInset
  adapted: tac.application.window.titleBarButtonInset is ignored on Windows: the system caption buttons stay where Windows draws them, at the top trailing corner. The page reads their size from --tac-titlebar-height and --tac-titlebar-trailing-inset.

tac.application.menus
  honored: items in the File, View and Help menus of the window's menu bar, or of the window menu under an integrated title bar; a route item opened its page, and a menu action and its shortcut reached the page inside WebView2 on a signed-in Windows desktop (N1, SD1)

tac.application.tray
  honored: a notification-area icon: a click opens the window, the context menu holds Open, the declared items and Exit, and a declared item's event reaches the page (ADR 0107, SD1)

tac.application.tray.template
  adapted: tac.application.tray.template applies only to the macOS menu bar. The Windows notification area shows the icon in its own colors.

tac.application.tray.closeHidesWindow
  honored: closing the window hides it, and its page keeps running until Exit; a click on the icon shows it again (SD1)

tac.application.tray.dock
  adapted: tac.application.tray.dock applies only to the macOS Dock. The Windows taskbar shows the app only while its window is open.

tac.application.rust
  honored: vendored crates linked into the app's Rust services

tac.application.rust.executables
  honored: helper programs in bin/ beside the app

tac.origin
  not applicable: tac.origin is for search engines and the web server. The Windows app bundle still holds sitemap.xml and robots.txt, but nothing reads them there.

tac.sitemap
  not applicable: tac.sitemap adds entries to sitemap.xml for search engines. The Windows app bundle holds the file, but nothing reads it there.

tac.scripts
  honored: the same page head as the web build

tac.blockingScripts
  honored: the same page head as the web build

tac.styles
  honored: the same page head as the web build

tac.styleSources
  honored: the same checked files, bundled into the app

tac.scriptSources
  honored: the same checked files, bundled into the app

tac.cache
  honored: the page applies the rules to Yon reads at tac.yon.origin in its own Cache Storage, which the web view keeps on disk; a network-first read answered from the cache with Yon stopped (SD1)

tac.metadata
  adapted: tac.metadata tags are written into each page, but search-engine and sharing tags do nothing inside the Windows app.

tac.application.permissions
  not applicable: tac.application.permissions is not used by the Windows app: the Windows location and notification settings decide, without a reason from the app.

tac.browserApis
  honored: the same grant list in the page

tac.browserApis clipboard
  honored: the Windows clipboard through the host bridge (browserApi.clipboard), both ways from a WebView2 page (SD1)

tac.browserApis share
  adapted: share in the Windows app opens the Windows share sheet for the app window (browserApi.share). ShareFinished arrives when the sheet opens, because Windows does not tell the app whether the user shared. The sheet opened from a WebView2 page on a signed-in Windows desktop (SD1).

tac.browserApis notifications
  adapted: notifications in the Windows app are Windows toasts (browserApi.notifications). Windows shows them only for the installed MSIX package with notifications turned on for the app, so an unpackaged build answers denied to requestPermission. A toast from the installed package reached the notification history on a signed-in Windows desktop (SD1).

tac.browserApis geolocation
  honored: the web view's navigator.geolocation and the Windows location service, granted by the host's PermissionRequested decision only for the app's own pages; every other web view permission is denied (SD1)

tac.browserApis preferenceStrings
  honored: the web view's localStorage, kept on disk across a relaunch (SD1)

tac.nativeCapabilities
  honored: filePicker opens the Windows file dialog (IFileOpenDialog) for page, linked Rust and linked C# services, and for Swift and Kotlin services, which run as WebAssembly on Windows and reach the dialog through the page; the MSVC build selected a file in the Windows dialog and closed an unanswered one (SD1), and a page, a linked C# and a WebAssembly Kotlin FilePicker field chose, read and cancelled from a WebView2 page on a signed-in Windows 11 desktop (FP5)

tac.elements
  adapted: tac.elements are bundled into the Windows app for its own pages only. Other sites cannot load them from the app.

tac.python
  honored: Pyodide in the web view (ADR 0093); a Python service answered inside WebView2 on a signed-in Windows desktop (SD1)

tac.budgets
  not applicable: tac.budgets is checked only by web release builds. The Windows app loads its bundle from disk, so route sizes are not measured (ADR 0074).

tac.outgoing
  honored: the build checks request hosts and the resource handler's connect-src allows only them; a page fetch to an undeclared host was refused and the host saw no request (SD1)

tac.yon
  honored: the page sends Yon calls to tac.yon.origin and its connect-src allows it; linked Rust and C# HTTPClient calls go there through WinHTTP and HttpClient; scripts/windows/yon-reach.ps1 passed inside WebView2 on a signed-in Windows desktop (NET3, ADR 0103)

tac.go
  honored: the same Go WebAssembly build in the web view

tac.dotnet
  adapted: tac.dotnet.aot does not change C# services in the Windows app, because they are linked into the app as native code. F# services still compile ahead of time.

application lifetime services
  honored: Rust services that start with the app and stop when it quits

standard menu bar without declared items
  honored: File, Edit and Window menus, shown even when the manifest declares no items (SD1)

Edit menu
  honored: Undo, Redo, Cut, Copy, Paste and Select All; Redo is Ctrl+Y (SD1)

Window menu
  adapted: The Windows Window menu has Minimize and Maximize, with no shortcuts.

menu shortcuts with control
  adapted: A shortcut with control gets Ctrl on Windows, like command. Shortcuts that then collide stop the build (TY1601).

page accessibility (roles and names through the system accessibility API)
  honored: the pages reach UI Automation through WebView2, with Edit, Button, Hyperlink, Text and Heading roles (AX2, SD1)

window drag regions (data-tac-drag-region)
  honored: with titleBar "integrated", data-tac-drag-region becomes CSS app-region: drag, so WebView2 moves the window, a double-click maximizes or restores it, and a right-click opens the window menu (SD1)

external links
  honored: http, https and mailto links open in the default browser or mail app (ShellExecuteW), from a WebView2 page (SD1)

deep links
  honored: with tac.application.links, a link with a listed scheme opens the app at its route; the app registers the scheme under HKCU\Software\Classes, or its MSIX package declares it, and hands later links to the running window

background and foreground signal
  honored: ApplicationStateChanged on WM_ACTIVATEAPP and when the window is minimized or restored, heard by the page and linked Rust services (SD1)

stored data (IndexedDB, Cache API, LocalState)
  honored: kept on disk by the web view: localStorage, IndexedDB and the Cache API survive a relaunch (SD1)

service worker
  not applicable: The Windows app registers no service worker: its pages load from the app bundle. With tac.yon.origin set, the page applies tac.cache rules to Yon reads itself; without it, tac.cache has no effect in the app.

Content-Security-Policy
  honored: the native host policy; connect-src refused an undeclared host from a WebView2 page (SD1)

reaching Yon
  honored: the app's pages load from https://tachyon.local, so Yon calls go to tac.yon.origin across origins, from the page and from linked Rust and C# services, and the page holds a linked C# or Rust service's stream and socket clients (NET3, LS1); other absolute URLs go only to the hosts in tac.outgoing.hosts

natively linked service languages
  honored: Rust and C# services are linked into the app; other languages run in the page

build architecture (--arch)
  honored: --arch x64 or arm64

development code signing
  adapted: a Windows build without --release is a folder with an unsigned .exe. It runs on this machine, but SmartScreen may warn when it is copied to another one. Build with --release for an MSIX package signed with the certificate that TAC_WINDOWS_CERTIFICATE or TAC_WINDOWS_CERTIFICATE_THUMBPRINT names.

release packaging
  honored: ty bundle --target windows --release builds an MSIX package, <Name>.msix, with makeappx and signs it with signtool and the certificate that TAC_WINDOWS_CERTIFICATE (a .pfx file) or TAC_WINDOWS_CERTIFICATE_THUMBPRINT (a certificate in the store) names; TAC_WINDOWS_CERTIFICATE_PUBLISHER is the package publisher. Other builds are a folder with the .exe

incremental route reuse
  honored: routes are reused from the previous app's web folder; --no-incremental turns this off

byte-identical rebuilds
  honored: the Windows build compiles and links with /Brepro and keeps .obj files out of the output; two packaged builds give the same artifact-manifest.json digests

running without a signed-in desktop session
  not applicable: The Windows app needs a signed-in desktop session: WebView2 does not start without one (0x80070578), and an MSIX package does not install over SSH (0x80070005). scripts/windows/desktop-run.ps1 runs a command from SSH in the desktop session of the same signed-in user, through a one-time interactive scheduled task.
