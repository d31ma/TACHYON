Windows

name, short_name
  honored: the window title and the executable name

start_url
  honored: the page the app opens first

icons
  adapted: icons: the Windows app wraps the largest icon whose declared size is at most 256 pixels as its .ico file. With no such icon, the app has no icon. A --release MSIX package copies, without resizing, the smallest PNG icon that covers each tile (44, 50 and 150 pixels), or the largest PNG icon; with no PNG icon its tiles are plain squares in theme_color.

theme_color
  adapted: theme_color colors the title bar of the Windows 11 app, with black or white title text, when it is written as #rgb or #rrggbb. Other color forms, and Windows 10, keep the system title bar color. A run of the caption color on a signed-in Windows 11 desktop is still owed.

background_color
  not applied: background_color is not applied to the Windows app yet (WIN7).

display
  adapted: display "fullscreen" starts the Windows app borderless and full screen; the page leaves it only with the fullscreen window control. The other values open a standard window. A run with a real window on a signed-in Windows desktop is still owed.

orientation
  not applicable: orientation has no meaning for a Windows window.

tachyon (top-level)
  refused with TY1601: The top-level tachyon member is gone. Move its values into tac (ADR 0052).

other standard manifest members
  adapted: The Windows app does not use the standard members scope, id, description, lang, shortcuts, share_target, file_handlers, protocol_handlers or display_override. They are published only for browsers.

tac.application
  honored: the app's identity, window and menus

tac.application.id
  adapted: tac.application.id becomes the Windows assembly identity name with each dot changed to a hyphen. A --release build also makes it the MSIX package name, with every character other than a letter, digit, dot or hyphen changed to a hyphen; an id that is then shorter than 3 or longer than 50 characters stops the release build (TY1601). C# service storage and the telemetry file use it as written.

tac.application.version
  honored: the executable's file and product version, the manifest assemblyIdentity and, with --release, the MSIX package version; a version that is not one to three numbers up to 65535 stops the build (TY1601)

tac.application.build
  honored: the fourth number of the executable's file version and, with --release, of the MSIX package version; a build above 65535 stops the build (TY1601)

tac.application.minimumSystem
  adapted: On Windows, tac.application.minimumSystem.windows is the WebView2 Runtime version (86.0 unless set; 119.0 with a Dart, Kotlin or Java web service). The app checks it when it starts and explains a missing or older runtime instead of opening a blank window.

tac.application.links
  adapted: tac.application.links: the Windows app registers the listed schemes for the current user when it starts (a --release MSIX package declares them as windows.protocol extensions instead), and opens their links at their route, or at start_url when the route is unknown. A link that arrives while the app runs goes to the open window. Links to the listed hosts stay in the browser, because the app declares no app URI handlers.

tac.application.window.width, height
  honored: the client area, in device-independent pixels

tac.application.window.minWidth, minHeight
  honored: the smallest client area the user can drag to, in device-independent pixels

tac.application.window.controls
  run owed: close, fullscreen, maximize, minimize, resize and title; still to run: native_windows_controls_drive_a_real_win32_window and a page call inside WebView2 on a signed-in Windows desktop

tac.application.window.titleBar
  not applied: tac.application.window.titleBar "integrated" is built only for macOS. The Windows app keeps the standard title bar (ADR 0098, WIN3).

tac.application.window.titleBarButtonInset
  not applied: tac.application.window.titleBarButtonInset is used only with the integrated macOS title bar. The Windows app ignores it.

tac.application.menus
  run owed: items in the File, View and Help menus of the window's menu bar; still to run: a route item opening its page and a menu action reaching the page inside WebView2 on a signed-in Windows desktop (N1)

tac.application.rust
  honored: vendored crates linked into the app's Rust services

tac.application.rust.executables
  honored: helper programs in bin/ beside the app

tac.origin
  not applicable: tac.origin is for search engines and the web server. The Windows app bundle still holds sitemap.xml and robots.txt, but nothing reads them there.

tac.sitemap
  not applicable: tac.sitemap adds entries to sitemap.xml for search engines. The Windows app bundle holds the file, but nothing reads it there.

tac.scripts

  honored: the same page head as the web build

  honored: the same page head as the web build

tac.scriptSources
  honored: the same checked files, bundled into the app

tac.cache
  run owed: the page applies the rules to Yon reads at tac.yon.origin in its own Cache Storage, which the web view keeps on disk; still to run: an offline Yon read inside WebView2 on a signed-in Windows desktop

tac.metadata
  adapted: tac.metadata tags are written into each page, but search-engine and sharing tags do nothing inside the Windows app.

tac.application.permissions
  not applicable: tac.application.permissions is not used by the Windows app: Windows asks without a reason from the app.

tac.browserApis
  honored: the same grant list in the page

tac.browserApis clipboard
  adapted: clipboard in the Windows app uses the web view's navigator.clipboard, and no host test checks it yet (BA3).

tac.browserApis share
  adapted: share in the Windows app uses the web view's navigator.share, and no host test checks it yet (BA3).

tac.browserApis notifications
  adapted: notifications in the Windows app use the web view's Notification API. The host asks for no permission yet (BA3).

tac.browserApis geolocation
  adapted: geolocation in the Windows app uses the web view's navigator.geolocation. The host asks for no permission yet (BA3).

tac.browserApis preferenceStrings
  run owed: the web view's localStorage, kept on disk; still to run: a preferenceStrings write read back after a relaunch inside WebView2 on a signed-in Windows desktop

tac.nativeCapabilities
  run owed: filePicker opens the Windows file dialog (IFileOpenDialog) for page, linked Rust and linked C# services; still to run: the_windows_file_picker_selects_a_file_in_the_windows_dialog with MSVC, and a picker opened from a WebView2 page on a signed-in Windows desktop

tac.elements
  adapted: tac.elements are bundled into the Windows app for its own pages only. Other sites cannot load them from the app.

tac.python
  run owed: Pyodide in the web view (ADR 0093); still to run: a Python service inside WebView2 on a signed-in Windows desktop (ADR 0093)

tac.budgets
  not applicable: tac.budgets is checked only by web release builds. The Windows app loads its bundle from disk, so route sizes are not measured (ADR 0074).

tac.outgoing
  honored: the build checks request hosts and the resource handler's connect-src allows only them

tac.yon
  run owed: the page sends Yon calls to tac.yon.origin and its connect-src allows it; linked Rust and C# HTTPClient calls go there through WinHTTP and HttpClient, tested in the cloud under wine and .NET (ADR 0103); still to run: scripts/windows/yon-reach.ps1 inside WebView2 on a signed-in Windows desktop (NET3)

tac.go
  honored: the same Go WebAssembly build in the web view

tac.dotnet
  adapted: tac.dotnet.aot does not change C# services in the Windows app, because they are linked into the app as native code. F# services still compile ahead of time.

application lifetime services
  honored: Rust services that start with the app and stop when it quits

standard menu bar without declared items
  run owed: File, Edit and Window menus, shown even when the manifest declares no items; still to run: an app with no declared items inside WebView2 on a signed-in Windows desktop

Edit menu
  run owed: Undo, Redo, Cut, Copy, Paste and Select All; Redo is Ctrl+Y; still to run: the Edit commands inside WebView2 on a signed-in Windows desktop

Window menu
  adapted: The Windows Window menu has Minimize and Maximize, with no shortcuts.

menu shortcuts with control
  adapted: A shortcut with control gets Ctrl on Windows, like command. Shortcuts that then collide stop the build (TY1601).

page accessibility (roles and names through the system accessibility API)
  run owed: the pages reach UI Automation through WebView2; still to run: the UI Automation probe of scripts/windows/native-test.ps1 on a signed-in Windows desktop (AX2)

window drag regions (data-tac-drag-region)
  not applied: data-tac-drag-region does nothing in the Windows app yet, because its title bar is standard (WIN3).

external links
  honored: http, https and mailto links open in the default browser or mail app (ShellExecuteW)

deep links
  honored: with tac.application.links, a link with a listed scheme opens the app at its route; the app registers the scheme under HKCU\Software\Classes, or its MSIX package declares it, and hands later links to the running window

background and foreground signal
  run owed: ApplicationStateChanged on WM_ACTIVATEAPP and when the window is minimized or restored; still to run: WM_ACTIVATEAPP and minimizing inside WebView2 on a signed-in Windows desktop

stored data (IndexedDB, Cache API, LocalState)
  run owed: kept on disk by the web view; still to run: data kept across a relaunch inside WebView2 on a signed-in Windows desktop

service worker
  not applicable: The Windows app registers no service worker: its pages load from the app bundle, and the page applies tac.cache rules to Yon reads itself.

Content-Security-Policy
  honored: the native host policy

reaching Yon
  run owed: the app's pages load from https://tachyon.local, so Yon calls go to tac.yon.origin across origins, from the page and from linked Rust and C# services; other absolute URLs go only to the hosts in tac.outgoing.hosts; still to run: scripts/windows/yon-reach.ps1 inside WebView2 on a signed-in Windows desktop (NET3)

natively linked service languages
  honored: Rust and C# services are linked into the app; other languages run in the page

build architecture (--arch)
  honored: --arch x64 or arm64

development code signing
  adapted: a Windows build without --release is a folder with an unsigned .exe. It runs on this machine, but SmartScreen may warn when it is copied to another one. Build with --release for an MSIX package signed with the certificate that TAC_WINDOWS_CERTIFICATE or TAC_WINDOWS_CERTIFICATE_THUMBPRINT names.

release packaging
  honored: ty bundle --target windows --release builds an MSIX package, <Name>.msix, with makeappx and signs it with signtool and the certificate that TAC_WINDOWS_CERTIFICATE (a .pfx file) or TAC_WINDOWS_CERTIFICATE_THUMBPRINT (a certificate in the store) names; TAC_WINDOWS_CERTIFICATE_PUBLISHER is the package publisher. Other builds are a folder with the .exe

incremental route reuse
  honored: routes are reused from the previous app's web folder; --no-incremental turns this off

byte-identical rebuilds
  run owed: the Windows build compiles and links with /Brepro and keeps .obj files out of the output; still to run: a_packaged_windows_app_is_byte_identical_when_built_twice in an MSVC developer prompt (TL2)

running without a signed-in desktop session
  not applicable: The Windows app needs a signed-in desktop session: WebView2 does not start without one (0x80070578), and an MSIX package does not install over SSH (0x80070005).
